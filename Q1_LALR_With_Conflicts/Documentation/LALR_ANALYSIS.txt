TASK 3: CONFLICT IDENTIFICATION
================================================================================

Number of Conflicts Found: 8 reduce/reduce conflicts (all in State 117)

Conflict State: 117
-------------------

Type of Conflict: REDUCE/REDUCE

The parser has completed parsing two different productions:
  1. stmt_block → '{' stmt_list '}'
  2. conditional_stmt → IF '(' condition ')' '{' stmt_list '}'

When the parser is in State 117 and sees certain lookahead symbols, it cannot
determine which production to reduce by.

================================================================================
TASK 4: DETAILED CONFLICT ANALYSIS
================================================================================

4a. State(s) Where Conflict Occurs:
-----------------------------------
State 117

How the parser reaches this state:
  The parser can reach State 117 through two different parse paths:

  Path 1: Parsing a statement block
    ... → '{' → stmt_list → '}' → State 117

  Path 2: Parsing a conditional statement with braces
    ... → IF → '(' → condition → ')' → '{' → stmt_list → '}' → State 117

  Both paths end with the same sequence: '{' stmt_list '}'
  This creates ambiguity about which production was being parsed.

4b. Type of Conflict:
--------------------
REDUCE/REDUCE CONFLICT

Definition:
  A reduce/reduce conflict occurs when the parser has completed two or more
  different productions and must decide which one to use for reduction. The
  parser has two complete items with the same lookahead symbols.

In our case:
  - Both items have the dot at the end (complete items)
  - Both can be reduced on the same lookahead symbols
  - The parser cannot distinguish which reduction to perform

Number of conflicts: 8
  (One for each of the 8 lookahead symbols: GO, TURN, PICK, DROP, IF, REPEAT,
   '{', '}')

4c. Exact Productions Involved:
-------------------------------

Production 26 (stmt_block):
  stmt_block → '{' stmt_list '}'

  Used for: Standalone code blocks within statements
  Example: { go 5; turn north; }

Production 31 (conditional_stmt):
  conditional_stmt → IF '(' condition ')' '{' stmt_list '}'

  Used for: Conditional statements with braced bodies
  Example: if (scan(north?) == obstacle) { turn east; }

Conflict Explanation:
  Both productions end with the same sequence: '{' stmt_list '}'

  When the parser sees:
    if (scan(north?) == obstacle) { go 5; }

  After parsing "{ go 5; }", the parser cannot determine if this block is:
    a) A stmt_block that happens to follow a condition
    b) The body of an if statement (conditional_stmt)

  The grammar is ambiguous because:
    - stmt can be stmt_block (rule 25)
    - conditional_stmt can have '{' stmt_list '}' (rule 31)
    - Both reduce to the same pattern when followed by the same lookaheads

Root Cause:
  1. We added stmt_block as a valid stmt type (rule 25: stmt → stmt_block)
  2. We allowed conditional_stmt with braces (rule 31)
  3. Both productions share the suffix '{' stmt_list '}'
  4. The grammar cannot use lookahead to distinguish between them

Bison's Resolution:
  Bison resolves this by choosing the production that appears first in the
  grammar file. In our case, it chooses rule 26 (stmt_block).

  This makes rule 31 (conditional_stmt with braces) effectively unreachable,
  which is why bison reports it as "useless in parser due to conflicts."

Impact:
  - The grammar will parse `if (...) { ... }` as two separate constructs:
    1. An if-condition expression (incomplete)
    2. A standalone stmt_block
  - This breaks the intended semantics of conditional statements with braces

Alternative Resolutions (if we wanted to fix it):
  1. Remove stmt_block as a standalone statement type
  2. Use different syntax for conditional vs. standalone blocks
  3. Refactor the grammar to eliminate the common suffix
  4. Use GLR parsing instead of LALR(1)

SUMMARY
================================================================================

This LALR(1) automaton construction demonstrates:

1. The grammar has been successfully augmented and item sets constructed
2. The automaton contains 132 states with well-defined transitions
3. A deliberate reduce/reduce conflict has been introduced in State 117
4. The conflict involves productions 26 and 31, both ending with '{' stmt_list '}'
5. The ambiguity arises from allowing stmt_block as a standalone statement
   while also having conditional statements with the same block syntax
6. Bison resolves this by preferring the first production (rule 26)
7. This makes the conflicting production (rule 31) unreachable

The conflict analysis clearly shows how LALR(1) parsers handle ambiguous
grammars and demonstrates the importance of careful grammar design to avoid
such conflicts in production parsers.
