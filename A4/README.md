## End to End Implementation Details

1. Lexing:
- `golem.l` tokenizes source code into keywords, operators, punctuation, literals, and identifiers.

2. Parsing + SDT:
- `golem.y` parses grammar rules and emits IR during reductions.
- Expression rules emit quadruples for `+`, `-`, `*`, `/`, `%`, unary minus, and assignment-like value moves.

3. IR core:
- Since we are attempting to build a compiler for specifying the behavior of autonomous agents operating within a discrete
two-dimensional grid world, we had to assume we had access to some non-conventional operations, specifically the following:
- create_canvas [arg1] [arg2] -> [-]
    Creates the grid canvas. Emitted from grid(w, h) after validating dimensions.
- load_golem [arg1] [arg2] -> [result]
    Creates/loads a golem at x=arg1, y=arg2 and stores its id in result.
    Emitted at blueprint entry using spawn argument slots.
- rot_golem [arg1] [arg2] -> [-]
    Rotates golem id=arg1 to angle arg2.
    Angle mapping used in codegen: north=0, east=90, south=180, west=270.
- go [arg1] [arg2] -> [-]
    Moves golem id=arg1 by arg2 steps in its current facing direction.
    Emitted from go expr; as go <active_id> <expr_temp>.
- load_obstacle [arg1] [arg2] -> [-]
    Marks obstacle placement at x=arg1, y=arg2.
    Emitted for every obstacle(x, y); in the grid block.
- check_empty [arg1] [arg2] -> [result]
    Returns 1 if target cell is empty, else 0. Used by directional condition lowering.

- IR storage and ordering:
    ir.c stores quads in a linked list and preserves source-level emission order.
    This guarantees printed IR appears top-to-bottom exactly as generated by parser actions.
- Name generation:
    new_temp() creates unique temporaries (t1, t2, ...).
    new_label() creates unique labels (L1, L2, ...).
- Emission API:
    emit_quad(op, arg1, arg2, result) appends one quadruple row.
    print_ir() renders a stable table with columns op, arg1, arg2, result.
    free_ir() releases all allocated IR nodes and resets counters.

4. Control flow lowering:
- `if` lowering (`if (cond) S`):
    1) evaluate condition into a boolean temp.
    2) emit `if_false_goto <cond_temp> <false_label>`.
    3) emit IR for `S`.
    4) emit `label <false_label>`.

- `if-else` lowering (`if (cond) S1 else S2`):
    1) evaluate condition into a boolean temp.
    2) emit `if_false_goto <cond_temp> <else_label>`.
    3) emit IR for `S1`.
    4) emit `goto <end_label>`.
    5) emit `label <else_label>` and IR for `S2`.
    6) emit `label <end_label>`.

- `repeat N { ... }` lowering:
    1) create loop counter temp and initialize it with `N`.
    2) emit `label <start_label>`.
    3) emit `if_eq <counter_temp> 0 <end_label>`.
    4) emit loop body IR.
    5) emit decrement `sub <counter_temp> 1 <counter_temp>`.
    6) emit back edge `goto <start_label>` and close with `label <end_label>`.

- Directional condition lowering (`>>`, `<<`, `^^`, `vv`):
    1) compute adjacent target coordinates using `+/- 1` from active golem position slots.
    2) emit `check_empty target_x target_y result_temp`.
    3) optionally emit `not` for obstacle or inequality forms.
    4) use resulting boolean with `if_false_goto` in branch lowering.

- Calling convention used by control-flow lowering:
    construct is treated as entry block (main-like).
    each spawn writes x/y into shared spawn slots and jumps to a blueprint label.
    blueprint entry performs load_golem from those slots, then executes body IR.
    blueprint/construct blocks use labels and gotos for explicit CFG edges.

5. Diagnostics and safety:
- Semantic checks include negative dimensions/coordinates, negative repeat counts, divide-by-zero, and modulo-by-zero.
- Syntax and semantic diagnostics are printed with line numbers.
- On error, parser exits cleanly without crashing.

6. Output stage:
- On successful parse, quadruples are printed in tabular format.
- On failure, diagnostics are printed and allocated IR is cleaned up.
